# Задача № 6. Вычисление полинома

**Ограничение по времени:** 1 секунда.  
**Ограничение по памяти:** 16 Мб.

## 1. Постановка задачи

Дан многочлен:

\[
P(x)=a_nx^n+a_{n-1}x^{n-1}+\ldots+a_2x^2+a_1x+a_0
\]

Необходимо вычислить значение данного многочлена для нескольких значений аргумента \(x\).

Поскольку степень многочлена может быть достаточно большой, вычисления необходимо производить по модулю `MOD`.

Формат входных данных:
- \(N\) — степень полинома, \(2\leq N\leq100000\);
- \(M\) — количество значений аргумента, \(1\leq M\leq10000\);
- `MOD` — модуль, \(10\leq MOD\leq10^9\);
- далее идут \(N+1\) коэффициентов;
- затем идут \(M\) значений аргумента.

Необходимо вывести \(M\) строк, каждая из которых содержит значение полинома по модулю `MOD`.

## 2. Используемый алгоритм

Для решения задачи используется **схема Горнера**.

Это алгоритм вычисления значения многочлена, позволяющий избежать непосредственного возведения аргумента в большие степени.

Обычное вычисление полинома потребовало бы вычислять:

\[
x^2,x^3,\ldots,x^n
\]

При больших значениях \(x\) и \(n\) такие вычисления становятся неэффективными.

Схема Горнера позволяет представить многочлен в следующем виде:

\[
P(x)=
(\ldots((a_nx+a_{n-1})x+a_{n-2})x+\ldots+a_1)x+a_0
\]

Таким образом, вместо вычисления отдельных степеней используется последовательное умножение на \(x\) и сложение с очередным коэффициентом.

## 3. Ход решения

Сначала считываем все коэффициенты многочлена. Они поступают от старшего коэффициента к младшему:

\[
a_n,a_{n-1},\ldots,a_0
\]

Для каждого значения аргумента \(x\) создаём переменную `value`, изначально равную нулю.

Затем последовательно обрабатываем коэффициенты:

\[
value=(value\cdot x+a_i)\bmod MOD
\]

После обработки последнего коэффициента переменная `value` содержит результат вычисления полинома.

Рассмотрим пример:

\[
P(x)=x^2+5x+4
\]

Пусть \(MOD=10\), а \(x=2\).

Вычисления:

1. Начальное значение:

\[
value=0
\]

2. Обрабатываем коэффициент 1:

\[
value=(0\cdot2+1)\bmod10=1
\]

3. Обрабатываем коэффициент 5:

\[
value=(1\cdot2+5)\bmod10=7
\]

4. Обрабатываем коэффициент 4:

\[
value=(7\cdot2+4)\bmod10=8
\]

Получаем:

\[
P(2)\bmod10=8
\]

Аналогично вычисляем значения для остальных аргументов.

## 4. Обоснование корректности

Схема Горнера является математически эквивалентным преобразованием исходного многочлена.

После обработки первых коэффициентов переменная `value` содержит значение соответствующей части вложенного выражения.

Каждая следующая операция умножает уже вычисленную часть на \(x\) и добавляет следующий коэффициент.

Поэтому после обработки всех \(N+1\) коэффициентов получается исходный многочлен.

Использование операции взятия остатка после каждого шага не изменяет итоговый результат по модулю `MOD`, поскольку:

\[
((a\bmod MOD)\cdot x+a_i)\bmod MOD
\]

эквивалентно:

\[
(a\cdot x+a_i)\bmod MOD
\]

Следовательно, алгоритм корректно вычисляет значение полинома по модулю.

## 5. Листинг программы

```python
import sys


def main():
    read = sys.stdin.buffer.readline

    n, m, mod = map(int, read().split())

    coefficients = [
        int(read()) for _ in range(n + 1)
    ]

    results = []

    for _ in range(m):
        x = int(read())
        value = 0

        for a in coefficients:
            value = (value * x + a) % mod

        results.append(str(value))

    sys.stdout.write('\n'.join(results))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Пусть:
- \(N\) — степень полинома;
- \(M\) — количество аргументов.

Для одного аргумента необходимо обработать все \(N+1\) коэффициентов.

Следовательно, время вычисления одного значения:

\[
O(N)
\]

Для всех аргументов:

\[
\boxed{T(N,M)=O(NM)}
\]

Для хранения коэффициентов требуется:

\[
O(N)
\]

Для хранения результатов:

\[
O(M)
\]

Итоговая дополнительная память:

\[
\boxed{S(N,M)=O(N+M)}
\]

**Важное замечание:** при максимальных ограничениях алгоритм выполняет около \(10^9\) итераций. Поэтому схема Горнера в данном виде не гарантирует прохождение ограничения в одну секунду. Это базовое корректное решение, но не подтверждённое по производительности на максимальном тесте. Для окончательной сдачи требуется более быстрый алгоритм многоточечного вычисления полинома, причём он должен учитывать, что модуль может быть составным.

# Задача № 9. Вырубка деревьев

**Ограничение по времени:** 1 секунда.  
**Ограничение по памяти:** 16 Мб.

## 1. Постановка задачи

Перед дворцом короля растёт \(n\) деревьев, расположенных в один ряд. Расстояния между соседними деревьями одинаковые.

После вырубки необходимо оставить ровно \(m\) деревьев, причём расстояния между соседними оставшимися деревьями должны быть одинаковыми.

Необходимо определить количество способов вырубки.

Ограничения:

\[
0\leq n,m\leq1000
\]

Пример:

Входные данные:

```text
5 3
```

Выходные данные:

```text
4
```

Возможные варианты:

```text
TTT..
.TTT.
..TTT
T.T.T
```

## 2. Используемый алгоритм

Для решения используется **математический подход с применением арифметической прогрессии**.

Перебирать все возможные комбинации деревьев не требуется.

Основная идея заключается в том, что после вырубки оставшиеся деревья должны образовывать арифметическую прогрессию.

Это позволяет получить математическую формулу и вычислить ответ за постоянное время.

## 3. Ход решения

Пронумеруем деревья числами от 0 до \(n-1\).

Пусть осталось \(m\) деревьев.

Если \(m\geq2\), их позиции можно представить в виде:

\[
a,\ a+d,\ a+2d,\ldots,a+(m-1)d
\]

Где:
- \(a\) — номер первого оставшегося дерева;
- \(d\) — одинаковое расстояние между оставшимися деревьями.

Расстояние \(d\) должно быть положительным целым числом.

Последнее дерево должно находиться в пределах исходного ряда:

\[
a+(m-1)d\leq n-1
\]

Отсюда:

\[
a\leq n-1-(m-1)d
\]

Количество возможных значений \(a\) для фиксированного \(d\):

\[
n-(m-1)d
\]

Теперь определим максимальное возможное расстояние:

\[
(m-1)d\leq n-1
\]

\[
d\leq\frac{n-1}{m-1}
\]

Следовательно:

\[
D=\left\lfloor\frac{n-1}{m-1}\right\rfloor
\]

Количество способов равно сумме:

\[
S=\sum_{d=1}^{D}(n-(m-1)d)
\]

Раскроем сумму:

\[
S=Dn-(m-1)\sum_{d=1}^{D}d
\]

Используем формулу суммы первых \(D\) натуральных чисел:

\[
1+2+\ldots+D=\frac{D(D+1)}{2}
\]

Получаем итоговую формулу:

\[
\boxed{
S=Dn-\frac{(m-1)D(D+1)}{2}
}
\]

Таким образом, вместо перебора всех комбинаций достаточно выполнить несколько арифметических операций.

### Обработка граничных случаев

Необходимо отдельно рассмотреть следующие ситуации.

**Случай 1.** Если \(m=0\), нужно удалить все деревья. Существует один способ.

**Случай 2.** Если \(m=1\), можно оставить любое из исходных деревьев:

\[
S=n
\]

**Случай 3.** Если \(m>n\), невозможно оставить больше деревьев, чем было изначально:

\[
S=0
\]

**Случай 4.** Если \(m=n\), можно ничего не вырубать:

\[
S=1
\]

Для этого случая общая формула также даёт правильный результат.

## 4. Обоснование корректности

Любой допустимый вариант оставшихся деревьев при \(m\geq2\) однозначно задаётся двумя параметрами: начальной позицией \(a\) и расстоянием \(d\).

Для каждого допустимого расстояния \(d\) существует ровно:

\[
n-(m-1)d
\]

возможных начальных позиций.

Разные пары \((a,d)\) задают разные наборы оставшихся деревьев.

Следовательно, суммирование количества начальных позиций по всем допустимым расстояниям учитывает каждый возможный способ ровно один раз.

Полученная формула вычисляет именно количество допустимых вариантов.

## 5. Листинг программы

```python
import sys


def count_ways(n, m):

    if m == 0:
        return 1

    if m == 1:
        return n

    if m > n:
        return 0

    d_max = (n - 1) // (m - 1)

    answer = (
        d_max * n
        - (m - 1) * d_max * (d_max + 1) // 2
    )

    return answer


def main():
    n, m = map(
        int,
        sys.stdin.buffer.read().split()
    )

    print(count_ways(n, m))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Алгоритм не использует циклы и перебор вариантов.

Количество выполняемых операций не зависит от размера входных данных.

Временная сложность:

\[
\boxed{T(n,m)=O(1)}
\]

Дополнительная память:

\[
\boxed{S(n,m)=O(1)}
\]

Использование математической формулы позволяет эффективно обрабатывать все допустимые значения \(n\) и \(m\).

# Задача № 17. Охрана

**Ограничение по времени:** 1 секунда.  
**Ограничение по памяти:** 16 Мб.

## 1. Постановка задачи

На секретной военной базе работают \(N\) охранников.

Сутки разделены на 10000 равных временных промежутков.

Для каждого охранника известны два значения:
- \(A\) — время прихода;
- \(B\) — время ухода.

Если охранник приходит в момент 5 и уходит в момент 8, это означает, что он охраняет шестой, седьмой и восьмой промежутки.

Необходимо определить, выполняются ли одновременно два условия:

1. Объект охраняется в любой момент времени хотя бы одним охранником.
2. Удаление любого охранника приводит к появлению промежутка времени, когда объект не охраняется.

Количество тестов:

\[
1\leq K\leq30
\]

Количество охранников в каждом тесте:

\[
1\leq N\leq10000
\]

Временные значения:

\[
0\leq A<B\leq10000
\]

## 2. Используемые алгоритмы

Для решения используются два алгоритмических приёма:

1. **Массив разностей** — для быстрого подсчёта количества охранников на каждом временном промежутке.
2. **Префиксные суммы** — для быстрого определения количества промежутков, которые охраняются ровно одним человеком.

Оба алгоритма позволяют избежать многократного перебора временных промежутков.

## 3. Ход решения

### 3.1. Подсчёт количества охранников

Создадим массив `diff` размером 10002.

Изначально все элементы равны нулю.

Для каждого охранника с интервалом прихода \(A\) и ухода \(B\) необходимо увеличить количество охранников на промежутках:

\[
A+1,A+2,\ldots,B
\]

Для этого используем массив разностей:

\[
diff[A+1] += 1
\]

\[
diff[B+1] -= 1
\]

Таким образом, мы отмечаем начало и конец интервала, не изменяя все элементы между ними.

После обработки всех охранников вычислим префиксные суммы массива разностей.

Обозначим количество охранников на промежутке \(i\) через \(coverage[i]\).

Тогда:

\[
coverage[i]=coverage[i-1]+diff[i]
\]

Если:

\[
coverage[i]=0
\]

значит, на данном промежутке нет ни одного охранника.

Следовательно, условие непрерывной охраны нарушено.

В этом случае сразу возвращаем `Wrong Answer`.

### 3.2. Проверка необходимости каждого охранника

Теперь необходимо убедиться, что удаление любого охранника приведёт к появлению неохраняемого промежутка.

Для этого каждому охраннику должен соответствовать хотя бы один промежуток, на котором находится только он.

То есть для охранника с интервалом \([A+1,B]\) должно существовать значение \(i\), при котором:

\[
coverage[i]=1
\]

Создадим массив `unique_prefix`.

Он будет хранить количество промежутков, охраняемых ровно одним человеком, от начала суток до текущего момента.

Формула:

\[
unique\_prefix[i]=unique\_prefix[i-1]+
\begin{cases}
1,&coverage[i]=1\\
0,&coverage[i]\neq1
\end{cases}
\]

Теперь количество уникально охраняемых промежутков конкретного охранника можно получить за постоянное время:

\[
unique\_prefix[B]-unique\_prefix[A]
\]

Если результат равен нулю, значит, охранник не имеет ни одного собственного промежутка.

Его удаление не нарушит охрану объекта.

В таком случае ответ — `Wrong Answer`.

Если каждый охранник имеет хотя бы один уникальный промежуток и все промежутки суток охраняются, ответ — `Accepted`.

## 4. Обоснование корректности

Рассмотрим первое условие.

Массив разностей корректно учитывает начало и конец каждого интервала охраны. После вычисления префиксных сумм значение `coverage[i]` равно количеству охранников, находящихся на дежурстве в соответствующий промежуток.

Поэтому проверка:

\[
coverage[i]>0
\]

для всех промежутков необходима и достаточна для непрерывной охраны.

Рассмотрим второе условие.

Удаление охранника нарушит охрану только в том случае, если существует хотя бы один промежуток, на котором он был единственным охранником.

Если на каждом промежутке его дежурства находятся два или более охранников, удаление этого человека не приведёт к появлению неохраняемого промежутка.

Следовательно, каждому охраннику должен соответствовать хотя бы один промежуток с:

\[
coverage[i]=1
\]

Префиксные суммы позволяют проверить существование такого промежутка внутри интервала каждого охранника.

Таким образом, алгоритм проверяет оба необходимых условия и правильно определяет результат.

## 5. Листинг программы

```python
import sys


class FastScanner:

    def __init__(self):
        self.stream = sys.stdin.buffer
        self.data = b''
        self.pos = 0

    def next_int(self):

        while True:
            if self.pos >= len(self.data):
                self.data = self.stream.read(65536)
                self.pos = 0

                if not self.data:
                    return None

            c = self.data[self.pos]

            if 48 <= c <= 57:
                break

            self.pos += 1

        value = 0

        while True:
            if self.pos >= len(self.data):
                self.data = self.stream.read(65536)
                self.pos = 0

                if not self.data:
                    return value

            c = self.data[self.pos]

            if 48 <= c <= 57:
                value = value * 10 + c - 48
                self.pos += 1

            else:
                self.pos += 1
                return value


def solve_case(n, scanner):

    diff = [0] * 10002
    intervals = []

    # Формирование массива разностей.
    for _ in range(n):

        a = scanner.next_int()
        b = scanner.next_int()

        intervals.append((a, b))

        diff[a + 1] += 1
        diff[b + 1] -= 1

    # Построение префиксных сумм.
    unique_prefix = [0] * 10001

    current = 0

    for i in range(1, 10001):

        current += diff[i]

        # Проверяем непрерывность охраны.
        if current == 0:
            return False

        # Считаем промежутки с одним охранником.
        unique_prefix[i] = (
            unique_prefix[i - 1] + (current == 1)
        )

    # Проверяем необходимость каждого охранника.
    for a, b in intervals:

        unique_count = (
            unique_prefix[b] - unique_prefix[a]
        )

        if unique_count == 0:
            return False

    return True


def main():

    scanner = FastScanner()

    k = scanner.next_int()

    answers = []

    for _ in range(k):

        n = scanner.next_int()

        if solve_case(n, scanner):
            answers.append("Accepted")
        else:
            answers.append("Wrong Answer")

    sys.stdout.write('\n'.join(answers))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Обозначим:
- \(N\) — количество охранников;
- \(T=10000\) — количество временных промежутков.

Формирование массива разностей требует:

\[
O(N)
\]

Вычисление префиксных сумм требует:

\[
O(T)
\]

Проверка всех охранников требует:

\[
O(N)
\]

Итоговая временная сложность:

\[
\boxed{T(N)=O(N+T)}
\]

Дополнительная память используется для:
- массива разностей;
- массива префиксных сумм;
- списка интервалов охранников.

Поэтому:

\[
\boxed{S(N)=O(N+T)}
\]

Так как \(T=10000\) является фиксированной величиной, алгоритм работает линейно относительно количества охранников.

# Задача № 18. Аттракцион

**Ограничение по времени:** 1 секунда.  
**Ограничение по памяти:** 16 Мб.

## 1. Постановка задачи

В парке развлечений кресла расположены в \(N\) рядах по \(M\) кресел.

Первоначальный номер кресла определяется формулой:

\[
v=(i-1)\cdot M+j
\]

где:
- \(i\) — номер ряда;
- \(j\) — номер столбца;
- \(v\) — номер кресла.

После работы механизма некоторые ряды и столбцы были переставлены местами.

Необходимо восстановить первоначальное расположение кресел, используя не более 1000 операций.

Операция может представлять собой:
- `R X Y` — обмен двух рядов;
- `C X Y` — обмен двух столбцов.

Ограничения:

\[
1\leq N,M\leq250
\]

## 2. Используемые алгоритмы

Для решения используются:

1. **Восстановление перестановки**.
2. **Массив обратных позиций**.
3. **Обмен элементов массива**.

Основная идея состоит в том, что перестановки строк и столбцов можно восстановить независимо друг от друга.

Хранить всю матрицу после считывания не требуется.

## 3. Ход решения

### 3.1. Восстановление координат кресел

Каждое кресло имеет первоначальный номер от 1 до \(N\cdot M\).

По номеру кресла можно определить его первоначальные координаты.

Номер первоначального ряда:

\[
r=(v-1)//M
\]

Номер первоначального столбца:

\[
c=(v-1)\bmod M
\]

В Python индексы начинаются с нуля, поэтому преобразование выполняется именно так.

Например, если:

\[
N=2,\quad M=2
\]

Исходная матрица:

```text
1 2
3 4
```

После перестановок получена матрица:

```text
4 3
2 1
```

Для первого элемента матрицы:

\[
v=4
\]

Получаем:

\[
r=(4-1)//2=1
\]

\[
c=(4-1)\bmod2=1
\]

Это означает, что кресло первоначально находилось во втором ряду и втором столбце.

### 3.2. Определение перестановки строк

При перестановке строк столбцы не меняют своего положения.

Поэтому все кресла одной текущей строки должны иметь одинаковый первоначальный номер ряда.

Достаточно взять первый элемент каждой строки.

Для каждой строки вычислим:

\[
row[i]=(matrix[i][0]-1)//M
\]

Полученный массив показывает, какой первоначальный ряд находится на каждой текущей позиции.

Например:

```text
row = [1, 0]
```

Это означает, что первый ряд должен поменяться местами со вторым.

### 3.3. Определение перестановки столбцов

Аналогично восстанавливаем столбцы.

При перестановке столбцов первоначальный номер столбца одинаков для всех элементов одного текущего столбца.

Поэтому достаточно рассмотреть первую строку:

\[
col[j]=(matrix[0][j]-1)\bmod M
\]

Полученный массив показывает первоначальные номера столбцов.

### 3.4. Восстановление перестановок

Теперь необходимо вернуть оба массива к первоначальному порядку:

\[
[0,1,2,\ldots,N-1]
\]

Для эффективного поиска нужного элемента создаём дополнительный массив `pos`.

В нём храним обратные позиции:

\[
pos[value]=index
\]

Это позволяет за \(O(1)\) определить, где сейчас находится необходимый элемент.

Далее перебираем позиции массива.

Если на текущей позиции находится неправильный элемент, находим позицию нужного элемента через `pos` и меняем их местами.

После обмена обновляем массив обратных позиций.

Каждая операция исправляет одну позицию, поэтому для восстановления перестановки длины \(N\) требуется не более \(N-1\) обменов.

После восстановления строк аналогично восстанавливаем столбцы.

### 3.5. Проверка ограничения на количество операций

Максимальное количество обменов строк:

\[
N-1
\]

Максимальное количество обменов столбцов:

\[
M-1
\]

Общее количество:

\[
K\leq N+M-2
\]

При максимальных значениях:

\[
K\leq250+250-2=498
\]

Поскольку:

\[
498<1000
\]

ограничение задачи выполняется.

## 4. Обоснование корректности

По условию кресла изменяли своё расположение только посредством обмена целых строк и столбцов.

Следовательно, все элементы одного текущего ряда имеют одинаковый первоначальный номер ряда.

Аналогично все элементы одного текущего столбца имеют одинаковый первоначальный номер столбца.

Поэтому массивы `row_permutation` и `col_permutation` полностью описывают итоговые перестановки.

Алгоритм восстановления перестановки на каждой итерации помещает необходимый элемент на соответствующую позицию.

Обратные позиции обновляются после каждого обмена, поэтому поиск следующего элемента остаётся корректным.

После восстановления строк и столбцов каждый элемент возвращается в первоначальную позицию.

Количество операций не превышает 498, что соответствует условию задачи.

## 5. Листинг программы

```python
import sys


def restore_permutation(permutation, command):

    n = len(permutation)

    # Создаём массив обратных позиций.
    pos = [0] * n

    for i in range(n):
        pos[permutation[i]] = i

    operations = []

    for i in range(n):

        # Определяем позицию нужного элемента.
        j = pos[i]

        if i == j:
            continue

        a = permutation[i]
        b = permutation[j]

        # Выполняем обмен.
        permutation[i], permutation[j] = b, a

        # Обновляем обратные позиции.
        pos[a] = j
        pos[b] = i

        operations.append(
            f"{command} {i + 1} {j + 1}"
        )

    return operations


def main():

    read = sys.stdin.buffer.readline

    n, m = map(int, read().split())

    row_permutation = []
    col_permutation = []

    # Считываем матрицу.
    # Сохранять всю матрицу не требуется.
    for i in range(n):

        row = list(map(int, read().split()))

        # Первоначальный номер ряда.
        row_permutation.append(
            (row[0] - 1) // m
        )

        # Первоначальные номера столбцов.
        if i == 0:

            for value in row:
                col_permutation.append(
                    (value - 1) % m
                )

    operations = []

    # Восстанавливаем ряды.
    operations.extend(
        restore_permutation(
            row_permutation, "R"
        )
    )

    # Восстанавливаем столбцы.
    operations.extend(
        restore_permutation(
            col_permutation, "C"
        )
    )

    print(len(operations))

    if operations:
        sys.stdout.write('\n'.join(operations))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Считывание матрицы требует:

\[
O(NM)
\]

Построение массива перестановки строк:

\[
O(N)
\]

Построение массива перестановки столбцов:

\[
O(M)
\]

Восстановление обеих перестановок:

\[
O(N+M)
\]

Итоговая временная сложность:

\[
\boxed{T(N,M)=O(NM)}
\]

Дополнительная память:
- массив перестановки строк;
- массив перестановки столбцов;
- массивы обратных позиций;
- список операций.

Следовательно:

\[
\boxed{S(N,M)=O(N+M)}
\]

Важной особенностью решения является то, что вся матрица не хранится в памяти. Это уменьшает потребление памяти с \(O(NM)\) до \(O(N+M)\), не ухудшая временную сложность.

# Задача № 19. Дек

**Ограничение по времени:** 1 секунда.  
**Ограничение по памяти:** 64 Мб.

## 1. Постановка задачи

Необходимо реализовать структуру данных «дек» (двусторонняя очередь).

Дек должен поддерживать четыре операции:

1. `push_back(value)` — добавить элемент в конец.
2. `push_front(value)` — добавить элемент в начало.
3. `pop_back()` — удалить и вывести последний элемент.
4. `pop_front()` — удалить и вывести первый элемент.

Максимальный размер дека задаётся во входных данных.

Если дек переполнен, при добавлении необходимо вывести `error`.

Если дек пуст, при удалении необходимо вывести `error`.

Использовать связный список запрещено.

Ограничения:

\[
n\leq5000
\]

\[
m\leq1000
\]

## 2. Используемый алгоритм

Для решения используется **циклический массив**.

Это структура данных, позволяющая реализовать дек с постоянным временем выполнения основных операций.

В отличие от обычного массива, при удалении первого элемента не требуется сдвигать все остальные элементы.

Массив рассматривается как кольцо: после последней позиции снова идёт первая.

## 3. Ход решения

Создадим массив фиксированного размера:

```python
data = [0] * capacity
```

Дополнительно будем использовать три переменные.

**Переменная `head`**

Хранит индекс первого элемента дека.

**Переменная `size`**

Хранит текущее количество элементов.

**Переменная `capacity`**

Хранит максимальный размер дека.

### 3.1. Добавление в конец

Для добавления элемента в конец необходимо определить следующую свободную позицию:

\[
index=(head+size)\bmod capacity
\]

После записи элемента увеличиваем размер:

\[
size=size+1
\]

Если:

\[
size=capacity
\]

до выполнения операции, значит, дек переполнен.

### 3.2. Добавление в начало

При добавлении в начало необходимо переместить указатель `head` на предыдущую позицию.

Формула:

\[
head=(head-1)\bmod capacity
\]

После этого записываем элемент в `data[head]` и увеличиваем размер дека.

Оператор остатка обеспечивает циклический переход между началом и концом массива.

### 3.3. Удаление из начала

Если дек пуст, выводим `error`.

Иначе:
1. Считываем элемент `data[head]`.
2. Выводим его.
3. Перемещаем `head` на следующую позицию.
4. Уменьшаем `size`.

Формула:

\[
head=(head+1)\bmod capacity
\]

### 3.4. Удаление из конца

Последний элемент находится по индексу:

\[
index=(head+size-1)\bmod capacity
\]

Считываем его и выводим.

После этого уменьшаем размер дека.

Указатель `head` при удалении с конца не изменяется.

## 4. Обоснование корректности

Циклический массив хранит все элементы дека последовательно в логическом порядке, начиная с позиции `head`.

При добавлении в конец элемент записывается сразу после последнего логического элемента.

При добавлении в начало указатель `head` перемещается назад, после чего новый элемент становится первым.

При удалении с начала указатель перемещается вперёд, а при удалении с конца уменьшается размер.

Таким образом, после каждой операции сохраняется правильный порядок элементов.

Проверки `size == capacity` и `size == 0` предотвращают переполнение и удаление из пустого дека.

Следовательно, реализация корректно выполняет все четыре операции.

## 5. Листинг программы

```python
import sys


def main():

    read = sys.stdin.buffer.readline

    n = int(read())
    capacity = int(read())

    # Создаём циклический массив.
    data = [0] * capacity

    head = 0
    size = 0

    answers = []

    for _ in range(n):

        command = read().split()

        operation = command[0]

        if operation == b'push_back':

            if size == capacity:
                answers.append("error")
                continue

            value = int(command[1])

            index = (head + size) % capacity

            data[index] = value

            size += 1

        elif operation == b'push_front':

            if size == capacity:
                answers.append("error")
                continue

            value = int(command[1])

            head = (head - 1) % capacity

            data[head] = value

            size += 1

        elif operation == b'pop_front':

            if size == 0:
                answers.append("error")
                continue

            answers.append(str(data[head]))

            head = (head + 1) % capacity

            size -= 1

        elif operation == b'pop_back':

            if size == 0:
                answers.append("error")
                continue

            index = (head + size - 1) % capacity

            answers.append(str(data[index]))

            size -= 1

    sys.stdout.write('\n'.join(answers))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Рассмотрим каждую операцию отдельно.

| Операция | Временная сложность |
|---|---|
| `push_back` | \(O(1)\) |
| `push_front` | \(O(1)\) |
| `pop_back` | \(O(1)\) |
| `pop_front` | \(O(1)\) |

Каждая операция выполняет фиксированное количество действий.

Для \(n\) команд:

\[
\boxed{T(n)=O(n)}
\]

Память:
- циклический массив занимает \(O(m)\);
- результаты операций занимают в худшем случае \(O(n)\).

Следовательно:

\[
\boxed{S(n,m)=O(m+n)}
\]

Использование циклического массива позволяет избежать сдвига элементов и обеспечивает выполнение всех основных операций за постоянное время.

# Задача № 21. Пирамидальная сортировка

**Ограничение по времени:** 1,5 секунды.  
**Ограничение по памяти:** 256 Мб.

## 1. Постановка задачи

Необходимо отсортировать результаты участников соревнования.

Для каждого участника известны:
- логин;
- количество решённых задач;
- размер штрафа.

Сортировка должна выполняться по следующим правилам:

1. Больше решённых задач — выше позиция.
2. При одинаковом количестве решённых задач меньший штраф — выше позиция.
3. Если количество задач и штраф совпадают, выше располагается логин, который раньше идёт в алфавитном порядке.

Количество участников:

\[
1\leq N\leq100000
\]

В задаче необходимо самостоятельно реализовать алгоритм сортировки кучей (Heapsort). Использовать встроенные алгоритмы сортировки и готовые реализации куч нельзя.

## 2. Используемый алгоритм

Для решения используется **пирамидальная сортировка (Heap Sort)**.

Она основана на структуре данных «бинарная куча».

Бинарная куча представляет собой почти полное бинарное дерево, которое удобно хранить в обычном массиве.

В данной задаче используется максимальная куча.

Её свойство заключается в том, что в корне находится максимальный элемент относительно выбранного порядка сравнения.

Однако в нашей задаче необходимо сортировать участников от лучшего к худшему.

Поэтому определим максимальный элемент как участника с худшим результатом.

Тогда после извлечения максимального элемента худший участник будет помещаться в конец массива.

В результате массив окажется отсортирован от лучшего участника к худшему.

## 3. Ход решения

### 3.1. Представление участника

Каждого участника будем хранить в виде кортежа:

```python
(login, solved, penalty)
```

Где:
- `login` — логин;
- `solved` — количество решённых задач;
- `penalty` — штраф.

### 3.2. Функция сравнения

Создадим функцию `is_worse(a, b)`.

Она будет возвращать `True`, если участник `a` имеет результат хуже участника `b`.

Сравнение выполняется последовательно по трём критериям.

Сначала сравниваем количество решённых задач:

\[
a.solved<b.solved
\]

Если у первого участника меньше решённых задач, он хуже.

Если количество задач совпадает, сравниваем штрафы:

\[
a.penalty>b.penalty
\]

Если штраф первого участника больше, он хуже.

Если совпадают оба числовых показателя, сравниваем логины:

\[
a.login>b.login
\]

Лексикографически более поздний логин считается худшим.

Таким образом, функция реализует порядок, необходимый для построения максимальной кучи.

### 3.3. Просеивание вниз

Для поддержания свойства кучи используется алгоритм `sift_down`.

Он позволяет восстановить структуру максимальной кучи после изменения положения элемента.

Если куча хранится в массиве с индексацией от нуля, то для элемента с индексом `i`:

Левый потомок:

\[
left=2i+1
\]

Правый потомок:

\[
right=2i+2
\]

Алгоритм сравнивает текущий элемент с потомками и выбирает наиболее плохого участника.

Если один из потомков хуже текущего элемента, они меняются местами.

Затем процедура повторяется для новой позиции элемента.

Просеивание завершается, когда текущий элемент находится на правильном месте.

### 3.4. Построение кучи

Первоначально участники расположены в произвольном порядке.

Для построения максимальной кучи необходимо выполнить просеивание вниз для всех внутренних узлов дерева.

Последний внутренний узел имеет индекс:

\[
\left\lfloor\frac{N}{2}\right\rfloor-1
\]

Поэтому начинаем обработку именно с него и движемся к корню.

```python
for i in range(n // 2 - 1, -1, -1):
    sift_down(arr, i, n)
```

После завершения цикла массив становится максимальной кучей.

В корне находится участник с самым плохим результатом.

### 3.5. Сортировка

После построения кучи выполняем сортировку.

На каждом шаге:

1. Меняем корневой элемент с последним элементом текущей кучи.
2. Уменьшаем размер кучи на единицу.
3. Выполняем `sift_down` для корня.
4. Повторяем операцию до тех пор, пока в куче не останется один элемент.

Худший участник постепенно перемещается в конец массива.

После завершения алгоритма все участники оказываются расположены в правильном порядке.

## 4. Обоснование корректности

Функция сравнения учитывает все три критерия сортировки и определяет, какой из двух участников имеет худший результат.

При построении максимальной кучи каждый родитель не хуже своих потомков по определённому нами порядку сравнения. Поэтому в корне всегда находится худший участник среди элементов кучи.

При обмене корня с последним элементом худший участник помещается на окончательную позицию в отсортированном массиве.

После уменьшения размера кучи алгоритм `sift_down` восстанавливает свойство максимальной кучи для оставшейся части массива.

Следовательно, на каждом шаге очередной худший участник помещается на своё окончательное место.

После завершения всех шагов массив оказывается отсортирован от лучшего участника к худшему.

Таким образом, алгоритм корректно выполняет требуемую сортировку.

## 5. Листинг программы

```python
import sys


def is_worse(a, b):
    """
    Проверяет, хуже ли участник a участника b.
    """

    # Меньше решённых задач — хуже.
    if a[1] != b[1]:
        return a[1] < b[1]

    # Больший штраф — хуже.
    if a[2] != b[2]:
        return a[2] > b[2]

    # Более поздний логин — хуже.
    return a[0] > b[0]


def sift_down(arr, root, size):
    """
    Просеивание элемента вниз
    в максимальной куче.
    """

    while True:

        largest = root

        left = 2 * root + 1
        right = 2 * root + 2

        # Проверяем левого потомка.
        if left < size:

            if is_worse(arr[left], arr[largest]):
                largest = left

        # Проверяем правого потомка.
        if right < size:

            if is_worse(arr[right], arr[largest]):
                largest = right

        # Если элемент находится на правильном месте.
        if largest == root:
            break

        # Меняем элементы местами.
        arr[root], arr[largest] = (
            arr[largest],
            arr[root]
        )

        root = largest


def heap_sort(arr):

    n = len(arr)

    # Построение максимальной кучи.
    for i in range(n // 2 - 1, -1, -1):

        sift_down(arr, i, n)

    # Сортировка извлечением максимального элемента.
    for end in range(n - 1, 0, -1):

        arr[0], arr[end] = arr[end], arr[0]

        sift_down(arr, 0, end)


def main():

    read = sys.stdin.buffer.readline

    n = int(read())

    participants = []

    for _ in range(n):

        login, solved, penalty = read().split()

        participants.append((
            login.decode(),
            int(solved),
            int(penalty)
        ))

    heap_sort(participants)

    output = []

    for participant in participants:
        output.append(participant[0])

    sys.stdout.write('\n'.join(output))


if __name__ == "__main__":
    main()
```

## 6. Анализ сложности

Обозначим количество участников через \(N\).

### Построение кучи

Построение кучи выполняется за:

\[
O(N)
\]

Несмотря на то, что отдельное просеивание может занимать \(O(\log N)\), суммарная сложность построения кучи составляет \(O(N)\).

### Сортировка

После построения кучи необходимо извлечь \(N-1\) элементов.

Каждое извлечение требует просеивания вниз:

\[
O(\log N)
\]

Поэтому общая сложность этапа сортировки:

\[
O(N\log N)
\]

### Итоговая сложность

\[
\boxed{T(N)=O(N\log N)}
\]

Сама сортировка выполняется непосредственно в исходном массиве.

Для перестановки элементов не создаются дополнительные массивы.

Поэтому дополнительная память самой сортировки:

\[
\boxed{S(N)=O(1)}
\]

При этом необходимо учитывать, что массив участников занимает \(O(N)\) памяти.

Таким образом, общая память программы:

\[
\boxed{S(N)=O(N)}
\]

Алгоритм не использует рекурсию и не создаёт дополнительный стек вызовов для просеивания.
