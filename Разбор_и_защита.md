## №6. Вычисление полинома

Файл: `task06_polynomial.py`.

### Как додуматься

Полином имеет вид `a_N*x^N + a_(N-1)*x^(N-1) + ... + a_0`. Считать каждую степень отдельно невыгодно. Перепишем выражение вложенно:

```text
((...(a_N*x + a_(N-1))*x + a_(N-2))*x ...)*x + a_0
```

Это схема Горнера. Для каждого аргумента достаточно пройти коэффициенты один раз. После каждого шага берём остаток по `MOD`; так все промежуточные числа остаются небольшими, а результат совпадает с остатком исходного полинома.

### Разбор кода по строкам

- **1–3:** заголовок файла и `sys`, который нужен для быстрого чтения и записи.
- **6–10:** функция `main`; вход разбивается на целые числа. Проверка на пустой ввод позволяет корректно завершить программу без ошибки.
- **12–15:** первые три числа задают степень `N`, количество аргументов `M` и модуль. Затем выбираются `N+1` коэффициентов и `M` значений `x`. Коэффициенты предполагаются записанными от `a_N` к `a_0`, как в формуле условия.
- **17–18:** готовится список ответов и начинается отдельный расчёт для каждого аргумента.
- **20:** начинаем схему Горнера со старшего коэффициента.
- **21–22:** для каждого следующего коэффициента выполняем `result = result*x + coefficient`, сохраняя только остаток по модулю.
- **23–25:** преобразуем ответы в строки и выводим по одному на строке.
- **28–29:** стандартная проверка, запускающая `main` при запуске файла.

### Сложность и объяснение преподавателю

Для одного аргумента выполняется `N` шагов, для всех — `O(N*M)` времени и `O(N+M)` памяти на считанные данные и ответы.

Можно объяснить так: «Я вычисляю значения полинома схемой Горнера: на каждом шаге умножаю накопленный результат на `x` и прибавляю следующий коэффициент. Так не нужно отдельно вычислять степени. Остаток можно брать на каждом шаге по свойству арифметики по модулю».

## №9. Вырубка деревьев

Файл: `task09_trees.py`.

### Как додуматься

Нужно выбрать `m` деревьев, оставив их на равных расстояниях. Если `m ≥ 2`, выбор полностью задают первый индекс `first` и шаг `step`:

```text
first, first+step, ..., first+(m-1)*step
```

Для фиксированного шага последний индекс не должен превышать `n`. Значит, первый индекс имеет `n-(m-1)*step` допустимых значений. Суммируем это количество по всем положительным шагам, которые ещё помещаются на улице.

### Разбор кода по строкам

- **1–3:** название задачи и импорт ввода.
- **6–9:** считываются `n` и `m`; пустой ввод обрабатывается отдельно.
- **11:** `n` — всего деревьев, `m` — сколько надо оставить.
- **13–18:** граничные случаи. При `m=0` есть один способ оставить пустое множество; при `m=1` можно выбрать любое из `n` деревьев.
- **19–24:** для `m≥2` находим максимальный шаг целочисленным делением. Цикл перебирает все шаги от 1 до максимального, а формула в строке 24 добавляет число возможных начальных позиций.
- **26:** печатается количество вариантов.
- **29–30:** запуск `main`.

### Сложность и объяснение преподавателю

Время `O(n/(m-1))`, в худшем случае `O(n)`; дополнительная память `O(1)`.

Можно объяснить так: «Для прогрессии с `m` членами достаточно задать шаг и первый ствол. Для шага `d` последний ствол сдвинут на `(m-1)d`, поэтому начало можно поставить в `n-(m-1)d` местах. Складываю эти количества. Для нуля и одного оставшегося дерева считаю варианты отдельно».

## №17. Охрана

Файл: `task17_guards.py`.

### Как додуматься

Нужно проверить сразу два условия из формулировки: база всё время находится под охраной, и удаление любого охранника создаст промежуток без охраны. Первое условие означает, что покрытие нигде не равно 0. Второе означает, что у каждого охранника есть хотя бы один промежуток, где он дежурит один.

День разбит на 10000 промежутков. Охранник, прибывший в момент `A` и ушедший в `B`, покрывает отрезки `A+1, ..., B`. Разностный массив позволяет добавить весь такой диапазон двумя изменениями.

### Разбор кода по строкам

- **1–3:** название задачи и импорт `sys`.
- **6–13:** читаются все числа, количество тестов, позиция чтения и список ответов.
- **15–17:** для каждого теста считывается число охранников; `pos` указывает на следующее непрочитанное число.
- **19–22:** создаются разностный массив и список исходных интервалов. Охранник, пришедший в `A` и ушедший в `B`, покрывает промежутки `A+1, ..., B`.
- **23–29:** читаем интервалы, сохраняем их для последующей проверки каждого охранника и добавляем диапазон в разностный массив двумя изменениями.
- **30–31:** `coverage` хранит текущее покрытие, а `single_prefix[t]` — число промежутков от начала дня до `t`, где дежурит ровно один человек.
- **32–39:** префиксная сумма по разностям восстанавливает покрытие каждого промежутка. Ноль означает, что база вообще не охранялась; единица увеличивает префиксное число «одиночных» промежутков.
- **41–45:** для каждого охранника проверяем его собственный диапазон. Разность префиксов должна быть положительной — тогда существует хотя бы один промежуток, который останется без охраны при его удалении.
- **47–49:** добавляем ответ для теста и выводим все ответы.
- **52–53:** запускаем `main`.
- **42–43:** запускаем `main`.

### Сложность и объяснение преподавателю

Для одного теста время `O(N + 10000)`, память `O(N + 10000)`.

Можно объяснить так: «Сначала разностным массивом восстанавливаю число охранников на каждом временном отрезке и убеждаюсь, что нигде нет нулевого покрытия. Затем префиксной суммой отмечаю отрезки с покрытием 1. Для каждого охранника за O(1) проверяю, есть ли такой отрезок в его смене; это и означает, что его удаление создаст дыру».

## №18. Аттракцион

Файл: `task18_attraction.py`.

### Как додуматься

Места пронумерованы по строкам: номер `v` соответствует исходной строке `(v-1)//M` и исходному столбцу `(v-1)%M`. Перестановки строк не меняют состав строки, а перестановки столбцов не меняют исходную строку элементов. Поэтому сначала можно вернуть на места строки, после — столбцы.

На каждом шаге ищем текущую строку или колонку, где находится нужная метка, и меняем её с текущей позицией. Каждая операция записывается в ответ.

### Разбор кода по строкам

- **1–3:** заголовок и импорт ввода.
- **6–9:** считывание входа с проверкой пустого файла.
- **11–16:** размеры таблицы и сама матрица мест.
- **18:** список будущих операций.
- **20–29:** восстанавливаются строки. Значение в первом столбце определяет исходный номер строки через `(value-1)//cols`. Если нужная строка стоит не на месте, меняем строки и записываем операцию `R`.
- **31–42:** после восстановления строк восстанавливаются столбцы. По первой строке вычисляем исходный номер столбца через `(value-1)%cols`. При необходимости меняем выбранные столбцы во всех строках и записываем `C`.
- **44–47:** выводим сначала количество операций, затем каждую операцию с нумерацией от 1.
- **50–51:** запуск `main`.

### Сложность и объяснение преподавателю

Время `O(N*M)` на чтение и обмены, память `O(N*M)`. Число операций не превышает `(N-1)+(M-1)`, то есть при ограничениях задачи — 498.

Можно объяснить так: «Номер места кодирует исходную строку и столбец. Сначала сортирую строки по исходной строке, затем столбцы по исходному столбцу; эти перестановки независимы. Я сохраняю все обмены, поэтому программа выводит не только число действий, но и сам способ восстановить порядок».

## №19. Дек

Файл: `task19_deque.py`.

### Как додуматься

Для дека нужны добавление и удаление с обоих концов. Кольцевой массив позволяет выполнять каждую операцию за `O(1)`: `head` хранит индекс первого элемента, `size` — число элементов, а индексы переходят через конец массива по модулю его вместимости.

### Разбор кода по строкам

- **1–3:** заголовок и импорт ввода.
- **6–9:** вход читается токенами; пустой ввод завершает программу.
- **11–17:** извлекаются число команд и вместимость. `values` — кольцевой массив, `head` — начало дека, `size` — число хранимых элементов, `pos` — позиция следующего токена.
- **19–21:** цикл читает очередную команду.
- **23–31:** `push_back`: считываем значение, проверяем переполнение, вычисляем свободный индекс справа и увеличиваем размер.
- **33–41:** `push_front`: после проверки сдвигаем `head` назад по кольцу, записываем значение и увеличиваем размер.
- **43–49:** `pop_front`: при пустом деке выводим `error`; иначе печатаем первый элемент, передвигаем `head` и уменьшаем размер.
- **51–57:** оставшаяся команда — `pop_back`. Индекс правого элемента вычисляется как `head+size-1` по модулю вместимости.
- **59:** выводятся результаты только тех команд, которые должны что-то напечатать.
- **62–63:** запускается `main`.

### Сложность и объяснение преподавателю

Каждая команда выполняется за `O(1)`, всего `O(Q)` времени и `O(M)` памяти.

Можно объяснить так: «Я храню элементы в кольцевом массиве. Левый индекс и размер определяют положение обоих концов; остаток по вместимости возвращает индекс к началу массива. При переполнении и удалении из пустого дека печатается `error`. Для вместимости 0 операции добавления сразу попадают в ветку переполнения, поэтому деления по модулю на ноль нет».

## №21. Пирамидальная сортировка

Файл: `task21_heapsort.py`.

### Как додуматься

Порядок участников задаётся лексикографическим сравнением трёх критериев: решённых задач по убыванию, штрафа по возрастанию, логина по возрастанию. Встроенную сортировку не используем: строим двоичную кучу и применяем heapsort.

В куче вершина должна быть самым «худшим» участником. Каждый раз переносим его в конец неотсортированной части. После всех извлечений в начале массива оказываются лучшие участники.

### Разбор кода по строкам

- **1–3:** заголовок и импорт ввода.
- **6–12:** `is_worse` реализует порядок из условия. Возвращает `True`, если первый участник должен стоять позже второго.
- **15–16:** объявление `sift_down`; куча рассматривается в полуинтервале от 0 до `end`.
- **17–20:** вычисляется левый ребёнок; отсутствие ребёнка означает, что просеивание завершено.
- **22–25:** выбирается худший из двух детей.
- **27–31:** если выбранный ребёнок хуже родителя, они меняются местами; просеивание продолжается на новой позиции. Если нет — куча уже восстановлена.
- **34–47:** `main` считывает участников и сохраняет для каждого логин, число решённых задач и штраф.
- **49–51:** куча строится снизу вверх: достаточно просеять все узлы, у которых есть дети.
- **53–56:** худший элемент меняется с последним в куче; размер кучи уменьшается на один, после чего восстанавливается свойство кучи.
- **58:** печатаются логины в итоговом порядке.
- **61–62:** запуск `main`.

### Сложность и объяснение преподавателю

Построение кучи `O(N)`, затем `N` извлечений по `O(log N)`: итог `O(N log N)` времени и `O(1)` дополнительной памяти помимо массива участников.

Можно объяснить так: «Сравнение участников оформлено отдельно, чтобы три критерия применялись в заданном приоритете. В куче наверху находится худший участник; извлечение худших в конец оставляет в начале массива правильный порядок. Так реализуется heapsort без встроенной сортировки».
